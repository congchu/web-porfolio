Architecting Real-Time Streaming Telemetry with RxJS & Angular in Enterprise Systems

Author: Nguyen Minh Chau Technical Insight 2025 Enterprise Architecture

1. Technical Challenges in High-Frequency Streaming

During the development of The Disaster Prevention Software at Onsite Viettel Net and Case Management Software at Icetea Software, one of the most demanding engineering hurdles was managing high-frequency incoming data: real-time emergency responder coordinates, weather telemetry feeds, and live legal case updates arriving at client workstations continuously every second.

Relying on traditional HTTP polling or ad-hoc local state variables repeatedly triggered Angular's default Change Detection cycles. This led to UI frame drops, sluggish map interactions, and redundant network traffic overhead.

2. Architectural Solution with RxJS Reactive Pipelines

To eliminate these bottlenecks, I implemented reactive pipelines powered by RxJS (Reactive Extensions for JavaScript) following strict Publisher/Subscriber decoupling:

  • debounceTime & distinctUntilChanged: Implemented across dashboard telemetry search filters, eliminating superfluous queries during user typing and cutting redundant backend requests by over 70%.
  • switchMap & mergeMap: Gracefully cancelled stale asynchronous requests when newer filter criteria or socket ticks arrived, ensuring the UI always reflected the authoritative server state.
  • shareReplay(1): Cached master lookups and reference data streams so multiple child widgets could subscribe without re-invoking network calls.

3. Integrating Asynchronous Queues (RabbitMQ & Redis)

At the backend layer with Java Spring Boot at TCI Thucuc Insurance, asynchronous queue processing was introduced using RabbitMQ & Redis. Heavy tasks—such as broadcasting multi-channel Telegram & Email alerts—were offloaded from the primary request thread into worker queues. This allowed critical APIs to return responses in under 50ms with high operational resilience.
